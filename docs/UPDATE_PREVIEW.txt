RELEASE 0.9.19.2 - CLEAN MAP. SAME LOOT.

Fresh session, familiar cyberdeck. We cleared the old map clutter, taught BLE to recognise an old acquaintance, and persuaded UP TO DATE to remember its day job.

## 🧭 New session. Clean map. Your loot stays.

**Before:** Wi-Fi/BLE points from earlier sessions could reappear on the map.
**Now:** each launch starts with a clean Wi-Fi/BLE map. Receive a device again, new or known, and it can appear in this session. Repeat receptions update the same observation. Points stay until you close the game, including after STOP and scheduled Wi-Fi/BLE switches. **No valid position, no map point.**

**Saved loot, logs, pending uploads, XP, levels, achievements and settings stay.** Your cyberdeck remembers the loot. The map is allowed to forget.

## 🧷 BLE: nice try, we've met

**Before:** some saved BLE addresses were not recognised after restarting, so an old acquaintance could collect the full 10 XP welcome bonus again. Names containing commas or unmatched quotation marks could confuse older CSV entries, hide following records or mix up names and positions in the history view. Some history scans also left CSV readers open.
**Now:** saved BLE identities are recognised correctly after restarting. Those names keep their correct protocol, and following entries are read separately. The history view reads saved names, signal strength and positions correctly, without rewriting old logs, and closes its files after reading. Known BLE devices get the existing **1 XP** repeat award; genuinely new BLE devices still get **10 XP**. A known device appears on the clean session map only after a new reception with a valid position.

Rebooting is not a witness protection programme.

## 📇 One address, two separate records

**Before:** when Wi-Fi and BLE shared the same address, saving a repeat could update the other protocol's entry in the WiGLE export.
**Now:** Wi-Fi and BLE keep separate saved records, even when their addresses match. A stronger signal refreshes only its own protocol's exported entry; a weaker or equal signal leaves that saved entry intact. Neither overwrites the other protocol's record.

The XP rules stay **15 XP for new Wi-Fi**, **10 XP for new BLE** and **1 XP for repeats**. Previously earned XP is neither recalculated nor taken away. Existing history, logs and pending uploads stay intact.

## 🗺️ Mesh: the last packet gets a seat

**Before:** a MeshCore/Meshtastic reception waiting to be processed just before OFF or a protocol switch could disappear from the map immediately.
**Now:** those waiting receptions are included in the OFF snapshot. Valid Node GPS or the existing **[RX GPS]** fallback places a marker. A later credible fix can fill a missing position for a node heard this session. Restarting keeps contacts and progress, while starting a fresh mesh map.

The existing OFF rule stays: **mesh markers disappear between 5 and 10 minutes, farther first**. Repeated STOP does not extend their deadlines; the other active protocol keeps its markers.

This fixes a reproduced software edge case. The radio behaviour reported in the photos still needs device testing.

## 📡 MC / MT: who's been here this session

**Before:** the main HUD had no MC/MT counters.
**Now:** **MC:** and **MT:** count unique nodes successfully registered this session, whether new or known, with or without coordinates. Repeat packets do not add another node. OFF and protocol switches keep the counts; restarting resets them.

Saved contacts, nodes heard this session and visible map markers are different numbers. The ready-radio icon and familiar WDG styling stay.

## ✅ UP TO DATE has a memory now

**Before:** a verified **UP TO DATE** result was lost after restarting the game.
**Now:** it survives reopening the update window and restarting, tied to the installed version and code. **R** and the startup check still work. A newer release replaces the status. Network failures stay errors; any retained earlier success is labelled **last verified**. New-release notices still appear only once per release.

One less thing on the cyberdeck with the memory of a goldfish.

## 🖥️ Release notes, now fluent in cyberdeck

**Before:** Update Game could display raw Markdown markers and emoji its font could not draw.
**Now:** the same English description is adapted automatically for the original WDG window: readable text, numbered yellow headings, dark title strips and spacing. The original font, colours, window and **nine visible rows** stay. GitHub and Discord keep their emoji and formatting.

## 🔄 The first restart still needs a human

**Before / Now:** installation and restart rules are unchanged.

If the running updater is **0.9.17, 0.9.18 or 0.9.19**, the first upgrade still needs **one manual relaunch**. After installation, press **Enter or Esc** to close the game, then start it again.

Updates performed by **0.9.19.1 or later** restart automatically after successful installation, including **0.9.19.1 → 0.9.19.2**. Preparation, cancellation and failure do not restart the game.

## 🧪 Checked in software. Still a candidate.

Software regressions cover BLE history after restart, existing XP rules, native note rendering and version filtering, session maps, mesh queues, counters, persistent update status and saved-data preservation.

The full software suite passed on our uConsole: **808/808, zero errors, failures or skips**, including both recorded Meshtastic replays and the real driver-code contracts with simulated transports. The original Pyxel renderer also passed **25 controlled scenes on the device screen**. Windows passed **802/808**, with six platform-dependent skips and no errors or failures.

**Physical RF reception has not been verified for this candidate.** Replays, software tests and synthetic screen scenes do not prove new radio reception.

**0.9.19.2 is a review candidate. Public Release and stable OTA publication await approval.**
