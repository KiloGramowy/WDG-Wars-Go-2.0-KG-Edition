RELEASE 0.9.19.2 - CLEAN MAP. SAME LOOT.

Fresh session, familiar cyberdeck. Less map clutter, better BLE memory, and an updater that remembers doing its homework.

## 🧭 Fresh map. Your loot stays.

**Before:** Wi-Fi/BLE points from earlier sessions could reappear on the map.
**Now:** every launch starts with a clean Wi-Fi/BLE map. New receptions bring back both new and known devices; repeats update the same session observation. Points stay until you close the game, including after STOP and scheduled Wi-Fi/BLE switches. **No valid position means no map point.**

**A fresh map does not erase saved loot, logs, pending uploads, XP, levels, achievements or settings.** Your cyberdeck remembers the loot. The map is allowed to forget.

## 🧷 BLE: nice try, we've met

**Before:** some saved BLE addresses were missed after restarting, so an old acquaintance could collect the full 10 XP welcome bonus again. Commas or unmatched quotes in names could also confuse CSV entries, hide following records or scramble names and positions in the history view. Some history reads left files open.
**Now:** supported current and older history entries retain their correct identities, names, signal strength and positions. Following records stay separate, and readers close their files. Old logs are not rewritten. Known BLE devices get **1 XP**; genuinely new BLE devices still get **10 XP**. A known device joins the clean map only after a new reception with a valid position.

Rebooting is not a witness protection programme.

## 📇 One address, two records

**Before:** Wi-Fi and BLE sharing the same address could overwrite or suppress each other's WiGLE export entry.
**Now:** each protocol keeps its own record. A stronger signal updates only that protocol's row; a weaker or equal signal leaves it intact. The other protocol's row stays untouched.

The XP rules remain **15 XP for new Wi-Fi, 10 XP for new BLE and 1 XP for repeats**. Previously earned XP is neither recalculated nor taken away. Reading and deduplicating history does not rewrite old logs or remove pending uploads.

## 🧹 Pending logs: take out the packet trash

**Before:** exports without usable GPS could hang around after an upload attempt, with no way to remove a selected pending file in the game.
**Now:** **PLUGINS → Pending Upload Logs** lists individual Wi-Fi, ADS-B, MeshCore and Meshtastic export files. Select one, press **D**, then **Y** to delete it or **N / Esc** to cancel. The list is available without an upload API key.

After an upload attempt, inactive export files with **no usable GPS records** are cleaned up automatically, without another question. Files containing any usable GPS records stay. Active sessions, uploads in flight and files that change during the operation are protected.

Deletion removes the selected export, not your progress: **XP, levels, achievements, contacts and known Wi-Fi/BLE identities stay**. Known devices still earn repeat XP after restarting. Discarding an old mesh export does not erase a newer reception or invent an upload receipt.

Some packets never found themselves. They do not need a permanent room in your log folder.

## 🗺️ Mesh: the last packet gets a seat

**Before:** a MeshCore/Meshtastic reception waiting to be processed just before OFF or a protocol switch could disappear from the map immediately.
**Now:** waiting receptions are included in the OFF snapshot. Valid Node GPS or the existing **[RX GPS]** fallback places a marker. A later credible fix can fill a missing position for a node heard this session. Restarting keeps contacts and progress while starting a fresh mesh map.

The existing OFF rule stays: **mesh markers disappear between 5 and 10 minutes, farther first**. Repeated STOP does not extend deadlines; the other active protocol keeps its markers. This fixes a reproduced software edge case; it does not establish the cause of earlier radio reports.

## 📡 MC / MT: this session's roll call

**Before:** the public main HUD had no MC/MT counters.
**Now:** **MC:** and **MT:** count unique nodes successfully registered this session: new or known, with or without coordinates. Repeat packets do not add another node. **Both counters stay visible**, so changing protocols keeps the session's earlier work in view. OFF and protocol switches retain the counts; restarting resets them.

Saved contacts, session counters and visible map markers are different numbers. The ready-radio icon and familiar WDG styling stay.

## ✅ UP TO DATE has a memory now

**Before:** a verified **UP TO DATE** result was lost after restarting the game.
**Now:** it survives reopening the update window and restarting, tied to the installed version and code. **R** and the startup check still work. A newer release replaces the status. Network failures remain errors; any retained earlier success is labelled **last verified**. New-release notices still appear only once per release.

One less thing on the cyberdeck with the memory of a goldfish.

## 🖥️ Release notes, now fluent in cyberdeck

**Before:** Update Game could display raw Markdown and emoji its font could not draw.
**Now:** the shared English description is adapted automatically for WDG: readable text, numbered yellow headings, dark title strips and spacing. The original font, colours, window and **nine visible rows** stay. GitHub and Discord keep their emoji and formatting.

## ↕️ Fn+U: give those labels some elbow room

**Before:** scrolling the terminal with **Fn+U / Page Up** could make the scroll indicator overlap the line count.
**Now:** both labels have separate space in the header, including longer counts. Same terminal, fewer typographical pile-ups.

## 🔄 The first restart still needs a human

**Before / Now:** installation and restart rules are unchanged.

If the running updater is **0.9.17, 0.9.18 or 0.9.19**, the first upgrade still needs **one manual relaunch**. After installation, press **Enter or Esc** to close the game, then start it again.

Updates performed by **0.9.19.1 or later** restart automatically after successful installation, including **0.9.19.1 → 0.9.19.2**. Preparation, cancellation and failure do not restart the game.

## 🧪 Checked on the cyberdeck

Software regressions cover history reopening, the **15 / 10 / 1 XP** rules, saved-data preservation, safe pending-log deletion and cleanup, mesh queues, counters, persistent update status and note rendering. Recorded Meshtastic replays and real driver-code contracts use controlled inputs. The original Pyxel renderer is also checked on the uConsole.

Software checks cover history reopening, XP rules, saved-data preservation, mesh queues, counters, update status and note rendering.
